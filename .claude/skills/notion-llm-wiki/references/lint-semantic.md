# lint-semantic — 의미 lint 체크리스트

구조 lint(`lint.js`)가 기계적으로 못 잡는 것을 사람 대신 내가 본다. **보고만 하고 raw 는 고치지 않는다.**
결과는 각 서비스 `conflicts.md` 에 반영하고 log 에 남긴다.

## 준비

1. `node .claude/skills/notion-llm-wiki/scripts/lint.js --json` 으로 구조 결과를 받는다 (경고 목록이 입력의 일부다).
2. `wiki/index.md` 로 서비스·카테고리별 raw 목록을 본다.

## 체크리스트

### S1 원본 간 모순
- 같은 서비스에서 **키워드가 겹치는 원본**(index 의 `키워드:`)을 짝지어 수치·기한·금액·조건을 대조한다.
  예: 법무 "14일" vs CS "7일". 요금 "9,900원" vs 소개 페이지 "9,000원".
- 둘 다 `확정` 이면 **충돌**. 하나가 초안이면 "진행 중" 으로만 기록(충돌 아님).
- 기록: `## 충돌` 표에 주제 / A (출처·상태·최종수정) / B (출처·상태·최종수정) / 발견일.

### S2 위키 ↔ 원본 불일치
- 위키 페이지의 `sources` 원본이 위키 `updated` 이후 바뀌었다는 경고(`stale`)가 있으면 원본을 다시 읽고 위키 서술이 여전히 맞는지 본다.
- 틀리면 ingest 로 고친다 (이건 위키 쪽이므로 고쳐도 된다). log 에 남긴다.

### S3 요약 속성 ↔ 본문 불일치
- raw `summary` 가 본문의 `## 요약` 이나 결론과 다르게 말하는 경우 (예: 요약은 "7일", 본문은 "14일").
- 기록: `conflicts.md` 충돌 표에 "요약 속성 불일치" 로. 담당자가 Notion 에서 고칠 일이다.

### S4 정책 없는 응대
- `doc_type: FAQ·응대` 인데 `## 근거 정책` 이 `없음` 또는 링크 없음.
- 기록: `## 정책 없는 응대` 목록 (페이지 · 담당 · 무엇에 대한 응대인가).

### S5 폐기됐지만 참조됨
- `status: 폐기` 인 원본을 다른 `확정` 원본이 `<mention-page>` 로 가리킨다 (Grep 으로 폐기 페이지의 id/URL 을 raw 전체에서 찾는다).
- 기록: `## 폐기됐지만 참조됨` (참조하는 페이지 → 폐기 페이지).

### S6 AI 초안 방치
- `author_type: AI` 또는 `사람+AI` 이면서 `status: 초안` 이고 `last_edited_time` 이 30일 이상 지난 것.
- 기록: `## 검토기한 경과` 표에 "AI 초안 미검토" 로.

### S7 검토기한·meta 없음 (구조 lint 경고를 그대로 옮긴다)
- `stale`(raw) → `## 검토기한 경과` 표 (페이지 / 담당 / 기한).
- `meta-missing` → `## meta 없음` 목록 (페이지 · 카테고리 · 안내: 등록 항목 만들기, `references/notion-authoring.md`).

## 출력

- `conflicts.md` 각 섹션을 갱신한다 (섹션마다 출처 링크, 없으면 "없음" + 색인 링크).
- `wiki/log.md` 에 `· lint-semantic ·` 항목: 새로 발견 N · 해소 N · 담당자별 할 일.
- 운영자에게 5줄 이내 요약. **"고쳤다" 고 말하지 않는다** — 발견했고, 누가 무엇을 고쳐야 하는지를 말한다.
