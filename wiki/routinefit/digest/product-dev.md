## 핵심 사실

1. 루틴 알림은 서버 스케줄러 발송과 기기 로컬 알림을 함께 쓰는 하이브리드 구조로 결정했다. 서버를 기본 경로로 두고 로컬 알림을 백업으로 예약한다 — [알림 발송 아키텍처](../../../raw/routinefit/product-dev/알림-발송-아키텍처-555555.md) (2026-08-25)
2. 서버는 FCM 과 APNs 로 발송하고 발송 기준 시간대는 KST 로 고정한다. 서버 발송이 성공하면 로컬 알림은 취소한다 — [알림 발송 아키텍처](../../../raw/routinefit/product-dev/알림-발송-아키텍처-555555.md)
3. 선택지 비교에서 서버 스케줄러는 시각 변경 즉시 반영이 장점이고 푸시 토큰 문제에 노출되는 것이 단점, 기기 로컬 알림은 네트워크 없이 동작하지만 문구 변경과 집계가 불가, 하이브리드는 중복 발송 방지가 필요하다고 적혀 있다 — [알림 발송 아키텍처](../../../raw/routinefit/product-dev/알림-발송-아키텍처-555555.md)
4. 2026-08-19부터 2026-08-21까지 iOS 사용자 일부에게 루틴 알림이 발송되지 않았다. 원인은 앱 재설치와 기기 복원 이후 APNs 토큰 갱신 요청이 서버에 반영되지 않은 것이다. Android 에는 영향이 없었고 기기 로컬 알림 백업은 일부만 동작했다 — [iOS 알림 미수신 장애 회고 (2026-08)](../../../raw/routinefit/product-dev/iOS-알림-미수신-장애-회고-2026-08-555555.md) (2026-08-22)
5. 장애 회고의 결정은 토큰 갱신 실패를 오류로 처리해 재시도 큐에 넣기, 발송 실패율 임계치 알람 붙이기, 알림 미수신 응대 문서 신설 3개다 — [iOS 알림 미수신 장애 회고 (2026-08)](../../../raw/routinefit/product-dev/iOS-알림-미수신-장애-회고-2026-08-555555.md)
6. 장애 회고의 할 일 중 토큰 갱신 경로 수정은 2026-08-21 배포 완료, 응대 문서 초안 작성은 완료로 표시돼 있다 — [iOS 알림 미수신 장애 회고 (2026-08)](../../../raw/routinefit/product-dev/iOS-알림-미수신-장애-회고-2026-08-555555.md)

## 진행 중 · 초안

- 데이터 보관 기간 정책 구현 노트 (초안) — 탈퇴 계정 데이터를 30일 보관 후 삭제하는 현재 구현 상태를 정리한 문서다. 절차 초안은 AI 로 정리하고 최민재가 코드와 대조해 검수했다(`author_type` 사람+AI). 법무가 보관 기간 단축을 검토 중이라 초안 상태로 둔다고 원본이 밝히고 있다 — [데이터 보관 기간 정책 구현 노트](../../../raw/routinefit/product-dev/데이터-보관-기간-정책-구현-노트-555555.md) (2026-09-06)
- 위 문서에 적힌 현재 구현 (초안) — 탈퇴 요청 시 삭제 예정 표시와 로그인 차단, `deleted_at` 에 요청 시점부터 30일 뒤 기록, 매일 KST 04시 정기 작업이 기한 지난 계정의 루틴·기록·알림 예약 삭제, 법정 보존 의무가 있는 결제 기록은 별도 보관소로 이전 — [데이터 보관 기간 정책 구현 노트](../../../raw/routinefit/product-dev/데이터-보관-기간-정책-구현-노트-555555.md)
- 30일 안에 재로그인하면 복구되는지 문의가 오며 현재 구현에서는 복구가 가능하다고 적혀 있다 (초안) — [데이터 보관 기간 정책 구현 노트](../../../raw/routinefit/product-dev/데이터-보관-기간-정책-구현-노트-555555.md)
