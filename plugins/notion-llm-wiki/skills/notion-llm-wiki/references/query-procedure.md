# query — 질문에 출처를 달아 답하기

임베딩·벡터 검색을 쓰지 않는다. 세 층을 순서대로 내려간다. 각 층에서 답이 확실해지면 아래 층은 **확인용**으로만 쓴다.

## 1층 — 색인 (`wiki/index.md`)

1. 파일 전체를 읽는다 (수백 줄이다 — 한 번에 읽힌다).
2. 질문에서 키워드를 뽑고 **동의어·영문·약어**를 스스로 확장한다 (환불 → 취소, refund, 청약철회 / 알림 → 푸시, notification).
3. `## 위키` 에서 서비스가 맞는 토픽·다이제스트를, `## 원본 (raw)` 에서 제목·요약·`키워드:` 가 맞는 줄을 고른다.
4. 줄의 표기를 읽는다: `(초안)`·`(검토중)` 은 확정 아님, `⏰` 는 검토기한 경과, `⚠` 는 meta 없음. 답의 신뢰도에 그대로 반영한다.

## 2층 — 위키 페이지

- 토픽이 있으면 토픽부터 (교차 카테고리 종합이 이미 돼 있다). 없으면 해당 카테고리 다이제스트.
- 토픽의 `## 충돌` 과 `conflicts.md` 를 **반드시** 본다 — 답에 "주의" 로 옮긴다.
- 위키 서술의 출처 링크를 따라 원본 1~2건을 열어 **수치·날짜가 위키와 같은지** 확인한다 (위키가 낡았을 수 있다).

## 3층 — 원문 grep

위키에 없거나 확인이 필요하면 `raw/` 를 찾는다:

```
Grep pattern="환불|취소|refund|청약철회" path="raw/routinefit" -i
Grep pattern="^keywords:.*(환불|refund)" path="raw" 
Grep pattern="^status: 확정" path="raw/routinefit/legal"      # 확정 문서만 좁히기
```

- 파일을 열면 frontmatter 의 `status`·`last_edited_time`·`source_url` 을 먼저 본다.
- `## 미확정 · 열린 질문` 에 있는 내용은 사실로 답하지 않는다.

## 답변 형식 (정본: docs/DESIGN.md 7절)

```
**답** — 한두 문장. 결론부터. 상태와 날짜를 괄호로. (확정, 2026-09-01 개정)

**근거**
1. [원본 제목](source_url) · 카테고리 · 상태 · 최종수정 YYYY-MM-DD — 인용 또는 요지
2. …

**주의** — 충돌·초안·검토기한 경과·meta 없음·원본 일부 누락이 있으면 여기. 없으면 줄을 생략.

**찾은 경로** — index → 토픽 "…" → raw N건 확인. 동기화 시각 YYYY-MM-DD HH:MM (이후 Notion 변경은 반영 안 됨)
```

- 근거의 링크는 raw frontmatter 의 **`source_url`** (Notion 원본). 미러 경로는 쓰지 않는다 — 독자는 Notion 을 연다.
- 동기화 시각은 `raw/.sync-state.json` 의 `syncedAt` (또는 index 의 "동기화:" 줄).
- 답에 없는 것을 덧붙이지 않는다. 원본이 "7일" 이면 "약 일주일" 로 바꾸지 않는다.

## 못 찾았을 때

```
**답** — 위키와 원본 어디에도 "…" 에 대한 페이지가 없습니다.

**찾아본 곳** — index 전체(raw N · wiki M), `raw/<svc>/` Grep: "a", "b", "c" → 0건.
**제안** — 담당 카테고리(예: 상품기획) DB 에 페이지가 없다면 논의된 적이 없거나 Notion 에 기록되지 않은 것입니다.
```

"없다" 는 유효한 답이다. 비슷한 것으로 채우지 않는다. 다만 **관련은 있지만 다른 질문에 답하는** 페이지가 있으면 "관련 페이지" 로 따로 적어 준다.

## 신선도

- 동기화가 24시간 이상 전이면 답 끝에 "`sync` 를 먼저 돌리면 더 최신일 수 있습니다" 를 붙인다.
- 원본의 `review_by` 가 지났으면 "검토기한 경과 — 담당 ○○○ 확인 필요" 를 주의에 넣는다.

## 환류 (선택)

같은 질문이 반복되거나 답이 원본 3개 이상을 종합했다면, 운영자에게 "이 답을 토픽 페이지로 남길까요?" 라고 **제안만** 한다.
만들 때는 ingest 절차와 wiki-schema 를 따른다 (출처·sources·log).
