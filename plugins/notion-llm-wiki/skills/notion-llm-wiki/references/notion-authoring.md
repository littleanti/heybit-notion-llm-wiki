# notion-authoring — 실무자에게 안내할 작성 규약 (요약)

정본은 `docs/DESIGN.md` 1·2절이다. 이 파일은 운영자가 실무자에게 **바로 붙여 줄 수 있는 길이**로 줄인 것이다.
`sync` 리포트에 "meta 없음" 이 나오거나, 실무자가 "어떻게 써야 하나" 를 물으면 이 내용을 안내한다.

## 새 페이지는 카테고리 DB 항목으로

서비스 페이지 → 카테고리 페이지 안의 **데이터베이스**(예: `루틴핏 · CS`)에서 `+ 새 항목` → 템플릿 선택.
채울 것은 **5개**만: **제목 · 문서유형 · 상태 · 요약(한 문장, 120자) · 담당자.** 나머지는 기본값·선택.

| 속성 | 값 |
|---|---|
| 문서유형 | 기획서 · 정책·규정 · 가이드·매뉴얼 · FAQ·응대 · 회의록 · 결정기록 · 분석·리포트 · 체크리스트 · 기타 |
| 상태 | 초안 → 검토중 → **확정** → 폐기. 위키는 **확정만 사실로** 씁니다 |
| 요약 | "이 페이지를 읽으면 무엇을 알게 되는가" 한 문장 — 색인이 이 문장으로 만들어집니다 |
| 키워드(선택) | 동의어·영문·약어: `환불, 취소, refund`. 검색이 이걸로 찾습니다 |
| 검토기한(선택) | 정책·규정은 작성일 + 180일이 기본. 지나면 "검토 필요" 로 표시됩니다 |
| 비밀등급 | 기본 `내부`. **`민감`** 이면 위키·미러 어디에도 들어가지 않습니다 |
| 위키제외 | 개인 메모 등 위키에 넣지 않을 페이지 |

## 본문 골격 (템플릿이 만들어 줍니다)

```
## 요약
## (유형별 섹션 — 정책은 적용 범위/규정/근거/예외, FAQ 는 상황/응대/근거 정책 …)
## 미확정 · 열린 질문     ← 없으면 "없음". 여기 적은 것은 위키가 사실로 쓰지 않습니다
## 변경 이력              ← - 2026-09-09 (이름) 무엇을 바꿨나
```

- 날짜는 `2026-09-09` 처럼 절대 날짜. "지난주" 금지.
- 다른 페이지를 언급할 때는 `@` 멘션. 제목만 적으면 연결되지 않습니다.
- FAQ 의 `## 근거 정책` 이 없으면 `없음 — 정책 필요` 라고 씁니다. 위키가 "정책 없는 응대" 로 모아 법무·기획에 보여 줍니다.

## 기존(레거시) 페이지는 옮기지 말고 등록

카테고리 DB 에서 `+ 새 항목` → 템플릿 **레거시 등록** → `원본` 에 옛 페이지 URL, 제목 복사, 문서유형·상태·요약·담당자 채움. **본문은 비워 둡니다** (본문은 원본에 그대로).
여러 개면 운영자에게 `register-legacy` 를 요청하세요 (제목+원본만 자동으로 채워 줍니다).

## AI 가 쓴 페이지

템플릿 **AI 초안**: 작성주체 `AI`, 상태 `초안`. 첫 섹션에 무엇을 근거로 만들었는지 적습니다.
사람이 확인하면 상태를 올리고 `최종확인일` 을 찍습니다. 그 전까지 위키는 `(초안)` 으로만 인용합니다.
