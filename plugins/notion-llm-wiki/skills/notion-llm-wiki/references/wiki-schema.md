# wiki-schema — 위키 규칙의 정본

`ingest` 와 `query` 를 시작하기 전에 읽는다. 사람이 읽는 설계 근거는 `docs/DESIGN.md` 3절과 `docs/TRD.md` ADR-004·005 에 있고,
이 파일은 그중 **Claude 가 작업할 때 지켜야 할 규칙만** 모았다. 둘이 어긋나면 docs 가 정본이고 이 파일을 고친다.

## 1. 계층과 소유권

| 경로 | 누가 쓰나 | 내가 할 수 있는 것 |
|---|---|---|
| `raw/**` | `sync.js` 만 | **읽기만.** 고치거나 만들지 않는다 |
| `wiki/**` (index·log 제외) | **나(스킬)** | 만들기·고치기. 지우기는 운영자 확인 후 |
| `wiki/index.md` | `build-index.js` | 손대지 않는다. 스크립트를 다시 돌린다 |
| `wiki/log.md` | 나 | **끝에 덧붙이기만** (append-only) |
| Notion 원본 | 사람 | 절대 손대지 않는다 (스크립트도 쓰기 경로가 없다) |

## 2. raw 파일 읽는 법

`raw/<service>/<category>/<제목>-<id6>.md`. frontmatter 키:

- `title`, `service`, `category` (slug), `service_name`, `category_name`
- `doc_type` — 기획서 · 정책·규정 · 가이드·매뉴얼 · FAQ·응대 · 회의록 · 결정기록 · 분석·리포트 · 체크리스트 · 기타. `null` 이면 meta 없음
- `status` — **`확정` 만 사실로 서술할 수 있다.** `초안`·`검토중` 은 "진행 중" 으로, `폐기` 는 이력·참고로만. `null` 은 meta 없음
- `author_type` — `AI` 또는 `사람+AI` 면 사람이 확인하기 전(`status` ≠ 확정)까지 참고 정보다
- `summary`, `keywords`(동의어·영문), `tags`, `owner`(이름), `review_by`(지나면 검토 필요), `verified_at`
- `source_url` — **출처 링크로 쓸 Notion URL** (본문이 있는 원본). `registry_url` 은 등록 항목(있을 때만)
- `meta_source` — `properties`(DB 항목) · `registry`(레거시 등록) · `inferred`(등록 안 된 레거시 → meta 없음)
- `last_edited_time` — 원본 최종 수정. `synced_at` — 미러 시각
- `notion_truncated`, `notion_unknown_blocks` — 참이거나 0 보다 크면 본문 일부가 빠져 있다. 서술에 `(원본 일부 누락)` 을 붙인다

본문은 Notion enhanced markdown 이다: `<callout>`, `<table>`, `<mention-page url>`, 탭 들여쓰기, `<br>`. 그대로 읽으면 된다.
`<mention-page …>제목</mention-page> ([제목](../cat/file.md))` 처럼 미러 내 링크가 덧붙어 있으면 그 파일을 따라간다.

본문 섹션 중 **`## 미확정 · 열린 질문`** 은 사실이 아니다. **`## 변경 이력`** 은 결정이 언제 바뀌었는지의 근거다.
**`## 근거 정책`** 이 `없음` 인 FAQ 는 "정책 없는 응대" 로 충돌 페이지에 모은다.

## 3. 위키 페이지 종류·경로·상한

| type | 경로 | 개수 | 만드는 기준 |
|---|---|---|---|
| `overview` | `wiki/<svc>/overview.md` | 서비스당 1 | 항상 |
| `digest` | `wiki/<svc>/digest/<category-slug>.md` | 서비스×카테고리당 1 | 그 카테고리에 raw 가 1개 이상 있으면 |
| `topic` | `wiki/<svc>/topics/<영문-kebab>.md` | 서비스당 **최대 15** | **원본 2개 이상 · 카테고리 2개 이상**에 걸친 주제일 때만(최소 조건이지 의무는 아니다 — "이 주제로 카테고리를 가로지르는 질문이 올 것인가" 로 고른다). 교차 서비스 주제는 `wiki/all/topics/…`, `service: all` |
| `conflicts` | `wiki/<svc>/conflicts.md` | 서비스당 1 | 항상 (비어 있으면 "없음" 으로 채운다) |

- 다이제스트는 **200줄 이내.** 넘치면 토픽으로 뽑아낸다.
- 페이지 하나는 **200KB 이내** (lint L8).
- 토픽 파일명은 영문 kebab-case (`refund-policy.md`). 한글 금지 — URL 로 언급된다.
- 토픽 15개를 넘겨야 할 것 같으면 만들지 말고 운영자에게 "가장 오래 안 갱신된 토픽을 다이제스트로 흡수할까" 를 제안한다.

## 4. frontmatter (모든 위키 페이지)

```yaml
---
title: 환불 정책                  # Notion 제목. topic 은 게시 때 "토픽: " 이 붙는다
type: topic                       # overview | digest | topic | conflicts
service: routinefit               # 설정의 slug. 교차 서비스는 all
category: cs                      # digest 에만
summary: 한 문장 (색인 한 줄이 된다. 120자 이내)
keywords: [환불, 취소, refund]      # 동의어·영문 — query 가 index 에서 이걸로 찾는다
sources:                          # 근거로 쓴 raw 경로 전부. lint 가 존재를 확인한다
  - raw/routinefit/legal/구독-환불-규정-555555.md
updated: 2026-09-09               # 내가 이 페이지를 마지막으로 손댄 날 (절대 날짜)
---
```

`sources` 에 없는 raw 를 본문에서 인용하지 않는다. 인용했으면 `sources` 에 추가한다 — 다이제스트가 다른 카테고리의 raw 를 인용해도 된다(그 경로를 `sources` 에 넣는다). `sources` 는 "카테고리 목록" 이 아니라 "실제로 읽고 근거로 삼은 것" 이다.

## 5. 서술 규칙

1. **H2 섹션마다 출처 링크 1개 이상.** 형식: `[제목](../../raw/<svc>/<cat>/<file>.md)` — 위키 파일 위치 기준 상대 경로.
   `wiki/<svc>/overview.md`·`conflicts.md` 에서는 `../../raw/…`, **`wiki/<svc>/digest/*.md` 와 `wiki/<svc>/topics/*.md` 에서는 `../../../raw/…`**.
   색인 링크도 같은 규칙: overview/conflicts 에서 `../index.md`, digest/topics 에서 `../../index.md`. 게시 때 원본 Notion URL 로 바뀐다.
2. 출처의 `status` 표기: 확정이면 표기 없음. 아니면 `(초안)` `(검토중)` `(폐기 — 참고만)` `(meta 없음)` `(원본 일부 누락)`.
   **확정이지만 `review_by` 가 지난 원본**은 여전히 사실로 서술할 수 있되 `(검토기한 경과)` 를 붙이고 conflicts 의 검토기한 경과 표에도 올린다.
   표기는 겹칠 수 있다 — 확정이면서 절단된 원본은 `(원본 일부 누락)` 만, 초안이면서 절단이면 `(초안 · 원본 일부 누락)`.
3. 날짜는 절대 날짜. "최근" 이라고 쓰지 않는다. 원본의 `last_edited_time` 이나 변경 이력의 날짜를 쓴다.
4. 수치·기한은 원본 표현 그대로 옮긴다 (7일을 "일주일" 로 바꾸지 않는다 — 검색과 대조가 어려워진다).
5. 원본끼리 다르면 어느 쪽도 고르지 않는다. 토픽의 `## 충돌` 과 `conflicts.md` 에 양쪽을 적는다. 어느 쪽이 더 최신인지(`last_edited_time`), 어느 쪽이 확정인지는 **사실로 적어도 된다**(표의 `비고` 열) — 판단은 독자가 한다.
   다이제스트에는 `## 충돌` 섹션이 없다 — 핵심 사실 항목 끝에 `⚠ 충돌 → [충돌 · 미확정](../conflicts.md)` 을 인라인으로 붙이고 `## 검토 필요` 에도 한 줄 둔다.
6. 원본에 없는 결론이 필요해 보이면 `> 추론: …` 인용 블록으로 분리하고, 무엇에서 추론했는지 적는다.
7. 표는 머리행 있는 단순 파이프 표만. 목록 중첩은 2칸 들여쓰기 (게시기가 탭으로 바꾼다).
8. 위키 페이지끼리의 링크는 상대 경로 `.md` 로 (`../conflicts.md`, `topics/refund-policy.md`).

## 6. 템플릿

### overview
```
## 이 서비스는
## 지금 알아야 할 것            ← 최근 30일 내 바뀐 확정 원본 중 last_edited_time 최신 5개, 날짜 포함
## 카테고리별 입구              ← 다이제스트 링크 + 한 줄
## 토픽
## 충돌 · 미확정               ← 개수와 링크
```
### digest
```
## 핵심 사실                    ← 확정 원본에서. 번호 목록, 항목마다 출처. 충돌은 항목 끝에 ⚠ 인라인(5.5절).
                                  확정 원본이 하나도 없으면 "확정 원본 없음" + 색인 링크
## 진행 중 · 초안               ← 초안·검토중 요지 + (초안)/(검토중). AI 작성이면 함께 표기
## 자주 찾는 페이지            ← 원본 링크 5~10 (원본이 그보다 적으면 전부) + 요약 속성 그대로. meta 없는 레거시는 (meta 없음) 으로 여기에
## 검토 필요                    ← 검토기한 경과 · 폐기됐지만 참조됨 · meta 없음 · 충돌
## 미확정 · 열린 질문           ← (선택) 이 카테고리 원본들의 미확정 섹션 요지. 없으면 conflicts 의 미확정에만 둔다
## 관련 토픽
```
### topic
```
## 한눈에                       ← 5줄 이내, 결론부터. 충돌이 있으면 첫 줄을 "⚠ 충돌 있음 — 아래 충돌 절 참조" 로 (이 줄 포함 5줄)
## 현재 규칙 · 사실             ← 확정 원본 종합, 항목마다 출처·날짜
## 카테고리별 관점              ← 기획은 / CS 는 / 법무는
## 충돌                         ← 없으면 "없음" (그래도 출처 링크 1개는 둔다: 확인한 원본)
## 미확정                       ← 원본들의 미확정 섹션을 모은다
## 이력                         ← 결정이 언제 어떻게 바뀌었나
```
### conflicts
```
## 충돌                         ← 표: 주제 / A (출처·상태·최종수정) / B (출처·상태·최종수정) / 발견일(이번 ingest 날짜) / 비고(어느 쪽이 최신·확정인가 — 사실만)
                                  충돌이 없으면 "없음" 뒤에 **대조한 값의 표**(주제 / 원본들 / 값)를 두어도 된다 — 검증했다는 증거이며 새 결론이 아니다
## 정책 없는 응대               ← FAQ 의 근거 정책이 "없음" 으로 시작
## 검토기한 경과                ← 표: 페이지 / 담당 / 기한
## meta 없음                    ← 등록 안 된 레거시 페이지
## 폐기됐지만 참조됨           ← 폐기 페이지를 확정 페이지가 링크
## 미확정                       ← 토픽에 속하지 않는 원본들의 미확정 사항 (토픽이 있는 것은 토픽의 미확정에)
```
섹션에 해당 항목이 없으면 `없음` 이라고 쓰되, **그 섹션에도 링크 1개**를 둔다 — lint L5 는 섹션 단위다.
링크 우선순위: 확인한 raw 원본 → 관련 위키 페이지 → 색인(`../index.md`, digest/topics 에서는 `../../index.md`).
템플릿에 없는 섹션을 **추가**하는 것은 허용된다(lint 는 섹션 이름을 검사하지 않는다). 템플릿 섹션을 빼는 것은 허용되지 않는다.

## 7. log.md 항목 형식

```
## 2026-09-09 · ingest · 변경 3 / 삭제 0

- 입력: raw/.sync-report.md (변경: …)
- 갱신: wiki/… — 무엇을 왜
- 판단: …
- 미확정: … (담당자 확인 필요)
```

## 8. 금지

- raw 수정 · index 수정 · log 의 기존 항목 수정
- 원본에 없는 수치·날짜·결론. (예외: **한 원본의 표나 목록을 세어서** 나오는 개수는 `(원본 표에서 집계)` 를 붙여 쓸 수 있다 — 여러 원본을 합쳐 계산한 값은 안 된다)
- 출처 없는 섹션
- `민감`/`위키제외` 로 표시된 내용을 어디선가 보았더라도 위키에 옮기는 것 (미러에 없어야 정상이다 — 있으면 `sync` 를 다시 돌리고 운영자에게 알린다)
- 사람 이름 외의 개인정보 (이메일·연락처)
