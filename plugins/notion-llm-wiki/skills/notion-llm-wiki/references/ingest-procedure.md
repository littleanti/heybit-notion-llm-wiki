# ingest — raw 변경분 → wiki 갱신 절차

전제: `references/wiki-schema.md` 를 읽었다. `wiki/log.md` 의 마지막 항목을 읽어 지난 판단과 미확정을 알고 있다.

## 0. 모드 결정

- `raw/.sync-report.md` 가 있고 `wiki/` 에 페이지가 있으면 → **증분**. 리포트의 추가·변경·이동·삭제 목록이 입력이다.
- `--full` 이거나 `wiki/` 가 비어 있으면 → **전체**. `wiki/index.md` 를 먼저 만들어(`build-index.js`) 전체 raw 목록을 얻고, 서비스별로 진행한다.
- 리포트에 **실패** 항목이 있으면 그 페이지는 이번 회차에서 다루지 않고 log 에 "다음 회차" 로 적는다.

## 1. 변경된 raw 읽기

변경 파일마다 frontmatter 를 먼저 읽고 다음을 메모한다 (메모는 머릿속/스크래치, 저장소에 쓰지 않는다):

- 서비스 · 카테고리 · `status` · `doc_type` · `keywords` · `last_edited_time`
- `## 변경 이력` 의 마지막 항목 — 무엇이 바뀌었는지 원본이 직접 말해 준다
- 수치·기한·금액 (환불 14일, 월 9,900원 …) — 다른 원본과 대조할 재료
- `## 미확정 · 열린 질문` 내용
- `<mention-page>` 로 연결된 다른 원본 — 그 원본도 열어 **같은 수치가 같은지** 확인한다
- `## 근거 정책` (FAQ) — `없음` 이면 정책 없는 응대

## 2. 영향받는 위키 페이지 정하기

| 변경 | 반드시 갱신 | 확인 후 갱신 |
|---|---|---|
| 어떤 raw 든 | 해당 서비스 `digest/<category>.md` | `overview.md` 의 "지금 알아야 할 것" (확정이고 30일 내면) |
| `keywords` 가 기존 토픽과 겹침 | 그 토픽 | — |
| 원본 2개 이상·카테고리 2개 이상이 같은 주제를 다루고 토픽이 없음 | 새 토픽 (상한 15) | — |
| 수치·기한이 다른 원본과 다름 | `conflicts.md` 충돌 표 + 관련 토픽의 `## 충돌` | — |
| FAQ 의 `## 근거 정책` 이 `없음` 으로 시작 (예: "없음 — 정책 필요") | `conflicts.md` 정책 없는 응대 | — |
| `review_by` 경과 (index 의 ⏰) | `conflicts.md` 검토기한 경과, 다이제스트 검토 필요 | — |
| `meta_source: inferred` (index 의 ⚠) | `conflicts.md` meta 없음, 다이제스트 검토 필요 | — |
| `status: 폐기` 인데 다른 확정 원본이 링크 | `conflicts.md` 폐기됐지만 참조됨 | — |
| 삭제·이동된 raw | 그 경로를 `sources` 나 본문에서 쓰는 모든 위키 페이지 (Grep `raw/…/옛파일명`) | — |

## 3. 쓰기

- 템플릿과 서술 규칙은 wiki-schema.md 5·6절. **섹션마다 출처 링크.**
- 다이제스트 "핵심 사실" 은 확정 원본만. 초안·검토중은 "진행 중 · 초안" 으로.
- 토픽 "한눈에" 는 결론부터 5줄(첫 줄 포함). 충돌이 있으면 첫 줄을 `⚠ 충돌 있음 — 아래 충돌 절 참조` 로 쓴다 (줄 안에 `## ` 를 넣지 않는다 — lint 가 새 섹션으로 오인한다).
- 다이제스트에 충돌을 적을 자리는 핵심 사실 항목 끝의 인라인 `⚠ 충돌 → [충돌 · 미확정](../conflicts.md)` 과 `## 검토 필요` 다.
- 토픽이 없는 원본의 미확정 사항은 `conflicts.md` 의 `## 미확정` 에 모은다.
- `updated` 를 오늘 날짜로. `sources` 에 실제로 읽은 raw 를 전부.
- 다이제스트 200줄·페이지 200KB 를 넘기지 않는다.

## 4. 색인·lint

```
node <스크립트 디렉터리>/build-index.js      # <스크립트 디렉터리> = SKILL.md 상단의 `${CLAUDE_SKILL_DIR}/scripts` (치환된 절대 경로)
node <스크립트 디렉터리>/lint.js
```

- **오류(E) 가 0 이 될 때까지** 위키 쪽을 고친다. `source-missing` 은 대개 출처 링크가 빠진 섹션이나 `sources` 경로 오타다.
  `orphan-wiki` 는 build-index 를 다시 돌리면 대개 사라진다.
- 경고(W) `meta-missing`·`stale` 은 고칠 대상이 아니라 **충돌 페이지에 반영할 입력**이다.

## 5. log

`wiki/log.md` 끝에 wiki-schema.md 7절 형식으로 덧붙인다. 특히 **판단**(왜 이 원본을 확정 사실로 썼는가 / 왜 충돌로 뒀는가) 과 **미확정**(누가 확인해야 하나) 을 남긴다. 다음 ingest 의 내가 읽는다.

## 6. 보고

운영자에게 5줄 이내: 입력 몇 건 → 갱신한 위키 페이지 → 새로 생긴 충돌/미확정 → lint 결과 → "publish 를 이어서 할까요?".

## 전체 재합성 순서 (--full)

1. `build-index.js` 로 raw 목록 확보.
2. 서비스마다: 카테고리 순서(설정 순)로 raw 를 읽으며 다이제스트 초안 → 카테고리를 가로지르는 주제 후보 메모 → 토픽(기준 충족분만) → conflicts → overview.
3. `build-index.js` → `lint.js` → 오류 0.
4. log 에 "전체 재합성" 항목.
