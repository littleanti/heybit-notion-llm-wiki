# setup 절차 — 위키 작업 공간 준비

`/notion-llm-wiki setup` 의 정본이다. **묻는 것은 나(Claude)가 하고, 파일을 만드는 것은 `scripts/setup.js` 가 한다.**
스크립트는 스스로 사람에게 묻지 않는다 — 비대화형 실행에는 stdin 이 없기 때문이다.

원칙 3개:

1. **추측하지 않는다.** 작업 위치·Notion 페이지·토큰은 전부 사람에게 묻는다. 하나라도 모르면 멈춘다.
2. **덮어쓰지 않는다.** `notion-wiki.config.json` 이나 `.env` 가 이미 있으면 스크립트가 중단한다. 그 사실을 그대로 전한다.
3. **토큰 값을 되풀이하지 않는다.** 화면·요약·`.env` 인용 어디에도 값을 적지 않는다 (SKILL.md 절대 규칙 5).

---

## 0. 먼저 현재 상태를 본다

```
node ${CLAUDE_SKILL_DIR}/scripts/setup.js --status
```

아무것도 바꾸지 않는다. 이미 준비가 끝나 있으면 (`→ 준비됐다`) 5번으로 바로 간다.

설정이 아직 없으면 스크립트가 **`⚠ 작업 위치를 확인한다`** 블록을 먼저 낸다 — 어디에 무엇이 만들어질지와,
위치가 수상한 이유(홈 디렉터리·플러그인 폴더 안·이미 다른 프로젝트)를 알려 준다.
**이 블록은 요약하지 말고 사람에게 그대로 전하고, 그 위치가 맞는지 확인받은 뒤에 1번으로 간다.**
위험 표시가 하나라도 있으면 특히 그렇다 — 되돌리려면 사람이 손으로 지워야 한다.

---

## 1. 작업 위치를 묻는다

위키 작업 공간은 `.env`·`notion-wiki.config.json` 이 놓이고 `raw/`·`wiki/`·`drafts/` 가 생길 디렉터리다.
**Claude Code 의 현재 작업 디렉터리가 기본값**이다.

`AskUserQuestion` 으로 묻는다:

> **질문**: 위키 파일을 어디에 둘까요?
> - **현재 폴더** (`<0번에서 출력된 절대 경로>`) — 여기에 `.env`·설정·`raw/`·`wiki/` 가 생깁니다 (권장)
> - **다른 폴더** — 경로를 알려주세요

다른 폴더를 고르면 이후 모든 명령에 `--root <경로>` 를 **뒤에** 붙인다.
경로를 받았으면 `--status --root <경로>` 를 다시 돌려 그 위치 상태와 `⚠` 블록을 다시 확인한다.

> 주의: `--root` 는 `setup.js` 만이 아니라 `sync.js`·`build-index.js` 등 **모든 스크립트**에 매번 붙어야 한다.
> 매번 붙이는 것이 번거로우면, 사람에게 그 폴더에서 `claude` 를 다시 열라고 권한다.

---

## 2. 무엇을 동기화할지(sync 대상) 묻는다

`notion-wiki.config.json` 이 이미 정상이면(0번에서 `설정  정상`) 이 절을 건너뛴다.

동기화 대상은 두 종류다. **둘 다 Notion 페이지 URL 을 그대로 받으면 된다** — 스크립트가 URL 에서 id 를 뽑는다.

1. **서비스 상위 페이지** (1개 이상) — 실무 문서가 들어 있는 팀/서비스의 최상위 페이지. 이 아래를 읽어 `raw/` 로 미러한다.
2. **위키 루트 페이지** (정확히 1개) — 합성한 위키를 게시할 **빈 페이지**. 서비스 루트와 **같으면 안 된다**
   (위키가 자기 출력을 다시 수집하게 되므로 스크립트가 거부한다).

`AskUserQuestion` 으로는 자유 형식 값을 받을 수 없으므로 **산문으로 묻는다.** 한 번에 필요한 것을 다 적는다:

> Notion 페이지 URL 두 종류가 필요해요.
>
> 1. **동기화할 서비스 상위 페이지** — 실무 문서가 들어 있는 페이지입니다. 여러 개면 전부 알려주세요.
>    각각 짧은 영문 별칭도 함께요 (예: 루틴핏 → `routinefit`). 별칭은 폴더 이름이 됩니다.
> 2. **위키를 게시할 빈 페이지** — 새로 하나 만들어 주세요. 위 서비스 페이지와 달라야 합니다.
>
> 아직 Notion 에서 **연결(Connection)을 추가하지 않았다면** 각 페이지에서 `•••` → `연결` → 만든 연결을 추가해 주세요.
> (하위 페이지에는 자동 적용됩니다.) 이게 빠지면 페이지가 하나도 안 보입니다.

영문 별칭을 사람이 안 주면 **내가 제안하고 확인받는다** (`루틴핏` → `routinefit`). 별칭은 영소문자·숫자·하이픈만 쓴다.

---

## 3. 설정 파일을 만든다

받은 값으로 한 번에 만든다. 서비스마다 `--service` 를 반복한다.

```
node ${CLAUDE_SKILL_DIR}/scripts/setup.js --init-config --service "<slug>|<이름>|<URL>" --wiki-root "<URL>"
```

- 형식은 `"<slug>|<이름>|<URL 또는 id>"` — 구분자는 `|` 다.
- 이미 파일이 있으면 **중단한다.** 덮어쓰지 않는다 — 그 사실을 전하고, 고치려면 파일을 직접 열라고 안내한다.
- 카테고리(상품기획·상품설명·상품개발·CS·법무·마케팅·기타)와 속성 이름은 **템플릿 기본값**이 들어간다.
  팀의 Notion 속성 이름이 다르면 5번의 점검에서 드러난다 — 그때 `properties` 를 고친다.

---

## 4. 토큰을 넣는 방법을 묻는다

`.env` 부터 만든다 (이미 있으면 스크립트가 손대지 않는다):

```
node ${CLAUDE_SKILL_DIR}/scripts/setup.js --init-env
```

토큰이 없으면 **발급부터 안내한다**:

> Notion 오른쪽 위 `설정` → `연결` → `새 연결`. 이름은 아무거나요 (예: `LLM Wiki`).
> 권한은 **콘텐츠 읽기 · 삽입 · 업데이트**와 **사용자 정보**를 켜 주세요.
> 만들면 `ntn_` 으로 시작하는 비밀 값이 나옵니다.

그 다음 **넣는 방법을 `AskUserQuestion` 으로 묻는다.** 임의로 고르지 않는다:

> **질문**: Notion 토큰을 어떻게 넣을까요?
> - **직접 붙여넣기 (권장)** — 제가 만든 `.env` 파일을 열어서 직접 넣으세요. **토큰이 대화 기록에 남지 않습니다.**
> - **여기에 알려주기** — 제가 `.env` 에 넣어 드립니다. 다만 **붙여넣은 토큰이 이 대화 기록에 평문으로 남습니다.**

### 4-A. 직접 붙여넣기를 고른 경우

`.env` 의 **절대 경로**를 알려 주고 멈춘다:

> `<절대 경로>` 를 열어서 `NOTION_TOKEN=` 뒤에 토큰을 붙여넣고 저장해 주세요. 끝나면 "됐어" 라고 알려주세요.

파일을 대신 열어 주지 않는다. 다 됐다고 하면 5번으로 간다. **`.env` 를 읽지 않는다** — 채워졌는지는 `--status` 가 알려 준다.

### 4-B. 여기에 알려주기를 고른 경우

사람이 준 토큰을 **Write 툴로 임시 파일 하나에 값만 한 줄** 적는다. 파일 위치와 이름에 규칙이 있다:

- **프로젝트 밖에 둔다** — 스크래치패드 디렉터리가 있으면 거기. 위키 작업 공간 안에 만들지 않는다.
- **반드시 `.tmp` 또는 `.token` 으로 끝나는 이름**을 쓴다 (예: `notion-token.tmp`).
  스크립트는 이 두 확장자만 지운다 — `--token-file` 오타가 엉뚱한 파일을 삭제하는 것을 막는 장치다.
  다른 이름을 주면 **읽지도 지우지도 않고 중단한다.**

그 다음 스크립트에 파일 경로만 넘긴다 — **토큰을 명령줄 인자로 넘기지 않는다**:

```
node ${CLAUDE_SKILL_DIR}/scripts/setup.js --set-token --token-file <임시 파일 경로>
```

스크립트가 `.env` 에 기록하고 **임시 파일을 지운다.** 출력에는 길이만 나오고 값은 나오지 않는다.
이후 답변에서 토큰을 되풀이하지 않는다.

> **끝나고 반드시 전한다**: 이 경로로 준 토큰은 **세션 기록(transcript)에 평문으로 남는다.**
> 지금 당장의 위험은 아니지만, 로그에 닿은 비밀값의 표준 대응은 교체다 —
> 작업이 끝나면 Notion 설정 → 연결에서 **이 토큰을 폐기하고 새로 발급**하기를 권한다.
> (새 토큰은 4-A 로 직접 넣으면 기록에 남지 않는다.)

## 5. 연결을 확인한다 (읽기만 한다)

```
node ${CLAUDE_SKILL_DIR}/scripts/check-notion.js
```

연결 이름·사용자 수·보이는 페이지 수·서비스 루트와 위키 루트가 보이는지·속성 이름 매핑을 확인해 준다. 쓰기는 하지 않는다.

자주 나오는 결과와 할 일:

| 나온 것 | 뜻 | 다음 |
|---|---|---|
| `접근 범위 페이지 0개` | 연결이 어느 페이지에도 추가되지 않았다 (**가장 흔하다**) | 2번의 연결 추가 안내를 다시 한다 |
| `API token is invalid` (401) | 토큰 값이 틀렸다 | 4번을 다시. `ntn_` 으로 시작하는 값 그대로인지 확인 |
| `서비스 … 안 보인다` | `rootPageId` 가 틀렸거나 그 페이지에 연결이 없다 | URL 을 다시 받아 설정을 고친다 |
| `설정에 있으나 이 DB 에 없는 속성: …` | Notion 속성 이름이 팀마다 다르다 | `notion-wiki.config.json` 의 `properties` 를 실제 이름으로 고친다 |
| `사용자 조회 실패` | 연결 권한에 **사용자 정보**가 없다 | 담당자(people) 속성을 쓸 거면 권한을 켠다 |

`NOTION_TOKEN 이 없습니다` 가 나오면 4번으로 돌아간다.

---

## 6. 다음을 묻는다

점검이 통과하면 이어서 할지 **묻는다.** 시키지 않은 `sync` 를 하지 않는다.

> 연결 확인됐어요. 이제 Notion 문서를 가져올까요? (`sync`)

`sync` 는 Notion 에 **쓰지 않는다** — 읽어서 `raw/` 로 미러할 뿐이다. 그 사실을 함께 알리면 사람이 안심하고 진행한다.
