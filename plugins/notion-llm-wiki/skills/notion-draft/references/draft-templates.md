# draft-templates — 문서유형별 본문 골격 (스킬용 정본)

정본은 저장소의 `docs/DESIGN.md` 2절과 10.4 표다. 이 파일은 스킬이 작성 중에 보는 요약이다.
골격 자체는 `scripts/draft-new.js` 가 만든다 — 손으로 섹션을 적지 말고 스크립트를 쓴다.

## 공통 규칙

- 모든 유형은 `## 요약` 으로 시작하고 `## 미확정 · 열린 질문` → `## 변경 이력` 으로 끝난다.
- 필수 섹션을 **빼지 않는다.** 필요한 섹션을 **추가**하는 것은 허용된다(필수 섹션의 상대 순서는 유지).
- `## 요약` 은 속성 `요약` 과 같은 한 문장 + 필요하면 3줄 이내 보충.
- `## 미확정 · 열린 질문` 은 비워 두지 않는다. 없으면 `없음`. 모르는 것은 여기에 **질문 형태로** 남긴다.
- `## 변경 이력` 은 `- YYYY-MM-DD (사람 이름) 무엇을 바꿨나`. 절대 날짜만 쓴다("지난주" 금지).
- 다른 페이지를 가리킬 때는 **Notion 페이지 URL** 로 링크한다 — 게시할 때 `@` 멘션으로 바뀐다.
  상대 경로(`../raw/...`)는 게시에서 해석되지 않고 텍스트만 남는다.
- 표는 표준 마크다운 파이프 표로 쓴다 — 게시할 때 Notion 표로 바뀐다.

## 유형별 필수 섹션

| 문서유형 | 필수 H2 섹션 (순서대로) | 이 유형을 고르는 기준 |
|---|---|---|
| `FAQ·응대` | 요약 / 상황 / 응대 / 근거 정책 / 미확정 · 열린 질문 / 변경 이력 | 고객 문의에 **무슨 말로 답할지**가 핵심일 때 |
| `정책·규정` | 요약 / 적용 범위 / 규정 / 근거·관련 결정 / 예외 처리 / 미확정 · 열린 질문 / 변경 이력 | 위키가 **사실로 인용할 규칙**을 정할 때 |
| `기획서` | 요약 / 배경 · 문제 / 목표 · 지표 / 범위 (포함 / 제외) / 상세 / 의존성 · 리스크 / 미확정 · 열린 질문 / 변경 이력 | 만들 것을 정의할 때 |
| `결정기록` | 요약 / 맥락 / 선택지 / 결정 · 이유 / 결과 · 영향 (알려진 것) / 미확정 · 열린 질문 / 변경 이력 | **무엇을 왜 골랐는지**를 남길 때 |
| `가이드·매뉴얼` | 요약 / 대상 / 절차 / 자주 겪는 문제 / 미확정 · 열린 질문 / 변경 이력 | 누가 따라 하는 절차일 때 |
| `분석·리포트` | 요약 / 질문 / 데이터·방법 / 결과 / 해석·한계 / 미확정 · 열린 질문 / 변경 이력 | 숫자로 답할 때. **한계를 반드시 적는다** |
| `체크리스트` | 요약 / 체크 항목 / 미확정 · 열린 질문 / 변경 이력 | 빠뜨리지 않는 것이 목적일 때 |
| `회의록` | 요약 / 본문 / 미확정 · 열린 질문 / 변경 이력 | 논의를 남길 때. 결정이 있으면 `결정기록` 을 따로 만든다 |
| `기타` | 요약 / 본문 / 미확정 · 열린 질문 / 변경 이력 | 위 어디에도 안 맞을 때만 |

## 섹션에 무엇을 쓰는가

| 섹션 | 내용 | 흔한 실수 |
|---|---|---|
| `상황` (FAQ) | 고객이 **실제로 쓰는 표현** 그대로. 같은 말을 키워드 속성에도 넣는다 | 내부 용어로 바꿔 적기 |
| `응대` (FAQ) | ① 그대로 복사할 수 있는 1차 응대 문구 ② 확인할 것 ③ 에스컬레이션 기준 | 문구 없이 방침만 적기 |
| `근거 정책` (FAQ) | 정책·규정 페이지 링크. 없으면 **`없음 — 정책 필요`** 라고 쓴다 | 비워 두기(위키가 "정책 없는 응대" 로 모으지 못한다) |
| `적용 범위` (정책) | 어느 서비스·어느 사용자·언제부터 | "전체" 라고만 쓰기 |
| `규정` (정책) | 번호 목록. **한 항목 = 한 규칙.** 예외는 "단," 으로 같은 항목 안에 | 여러 규칙을 한 문장에 넣기 |
| `예외 처리` (정책) | 규정대로 안 되는 경우 **누가** 판단하는가 | 생략 |
| `선택지` (결정기록) | 표: 선택지 / 장점 / 단점 | 고른 것만 적기 |
| `결과 · 영향` (결정기록) | **알려진 것만.** 추측은 미확정으로 | 예상을 사실로 적기 |
| `해석·한계` (분석) | 이 결과로 말할 수 있는 것과 **말할 수 없는 것** | 한계 생략 |

## 속성(frontmatter) 채우는 기준

| 속성 | 기준 |
|---|---|
| `title` | "무엇에 대한 무엇" 이 드러나게. 색인의 첫 열이다 |
| `summary` | **한 문장, 120자 이내.** "이 페이지를 읽으면 무엇을 알게 되는가" |
| `owner` | 질문이 생겼을 때 갈 사람. **이름을 정확히** (워크스페이스 사용자 이름과 같아야 게시된다) |
| `status` | 신규는 항상 `초안` |
| `keywords` | 검색에 쓸 **동의어·영문·약어** (`환불, 취소, refund`). RAG 없이 찾는 유일한 보조 장치다 |
| `tags` | 이 문서가 속한 주제 (`결제`, `온보딩`). 카테고리 이름을 태그로 반복하지 않는다 |
| `review_by` | 정책·규정은 작성일 + 180일이 기본 |
| `sensitivity` | 기본 `내부`. `민감` 은 미러·위키·색인 어디에도 들어가지 않는다 |
