# notion-draft

`입력 → 로컬 초안 → 사람 검토 → Notion` 한 방향 흐름이다. 규약의 정본은 `references/draft-templates.md` 와
저장소의 `docs/DESIGN.md` 10절이다. **`new` 와 `edit` 를 시작하기 전에 `references/draft-procedure.md` 를 읽는다.**

서브커맨드는 첫 인자(`$0`)로 정한다. 모르는 서브커맨드이거나 인자가 없으면 아래 표를 보여 주고 멈춘다.

| `$0` | 하는 일 | Notion 쓰기 | 필요한 것 |
|---|---|---|---|
| `new` | 준 내용으로 **새 페이지 초안**을 만든다 | 없음 | 설정 파일 |
| `edit` | 기존 페이지의 현재 속성·본문을 **초안으로 받아 온다** | 없음 | `NOTION_TOKEN` |
| `submit` | 초안을 검증하고 dry-run 을 보여 준 뒤, `--apply` 면 게시한다 | `--apply` 일 때만 | `NOTION_TOKEN` |

스크립트 디렉터리는 `${CLAUDE_SKILL_DIR}/scripts` 다. **아래 명령을 글자 그대로 실행한다** — `cd` 를 붙이지 않고,
`&&`·`;`·`|` 로 묶지 않고, 경로를 따옴표로 감싸지 않는다(권한 사전 승인이 단독 명령에만 걸린다).
현재 작업 디렉터리가 `notion-wiki.config.json` 이 있는 위키 프로젝트 루트여야 한다. 없으면 만들라고 안내하고 멈춘다.

## 절대 규칙

1. **필수 속성 5개를 추측하지 않는다.** 제목·문서유형·상태·요약·담당자 중 입력에서 알 수 없는 것은
   `AskUserQuestion` 으로 **한 번에 묶어서** 묻는다. 특히 **요약과 담당자**는 틀리면 색인과 문의 경로가 함께 틀어진다.
   `AskUserQuestion` 이 없는 세션(비대화형 `-p` 실행 등)이라면 **묻는 문장을 출력하고 거기서 멈춘다.** 빈 값으로 초안을 만들지 않는다
   (검증이 `draft-meta-missing` 으로 막지만, 그 전에 멈추는 것이 사람의 시간을 아낀다).
2. **원문에 없는 사실을 쓰지 않는다.** 준 내용에 없는 수치·기한·정책을 채우지 않는다. 모르는 것은
   `## 미확정 · 열린 질문` 에 질문으로 남긴다. 비워 두지 않는다("없음" 이라고 쓴다).
3. **Notion 에 쓰는 것은 `submit --apply` 뿐이다.** 그 전에 항상 dry-run 을 보여 주고 사람의 확인을 받는다.
4. **신규 페이지는 `상태: 초안`.** 확정으로 만들지 않는다 — Notion 에서 담당자가 확인한 뒤 올린다.
5. **수정은 사람이 쓴 문서를 덮어쓰는 일이다.** diff 를 보여 주고, 대상이 `확정` 이면 그 사실을 말한 뒤 확인을 받는다.
   `"중단:"` 으로 시작하는 메시지가 나오면 **다시 시도하지 않고** 그 이유를 사람에게 전한다.
6. **토큰을 출력하지 않는다.** `.env` 를 읽거나 인용하지 않는다.
7. **`raw/`·`wiki/` 를 손으로 고치지 않는다.** 미러는 `submit` 이 갱신한다.

## `new <내용 또는 지시>`

**먼저 읽는다**: `references/draft-procedure.md`, `references/draft-templates.md`.

1. 입력에서 **서비스 · 카테고리 · 문서유형 · 제목**을 판단한다. 애매하면 묻는다(카테고리와 문서유형은 목록이 정해져 있다).
2. 필수 속성 중 빠진 것을 `AskUserQuestion` 으로 한 번에 묻는다(규칙 1).
3. 골격을 만든다 — 섹션 누락을 막기 위해 **스크립트를 쓴다**:
   ```
   node ${CLAUDE_SKILL_DIR}/scripts/draft-new.js --service <slug> --category <slug> --type <문서유형> --title <제목> --owner <이름> --summary <한 문장> [--keywords a,b] [--tags a,b] [--review-by YYYY-MM-DD]
   ```
4. 만들어진 파일의 안내 주석(`<!-- ... -->`)을 지우고 각 섹션을 **준 내용으로만** 채운다 (Read → Edit).
   같은 주제의 기존 원본이 있으면 `raw/` 를 Grep 해 근거 링크(Notion URL)를 단다.
5. 사람에게 **초안 경로와 핵심 내용 5줄 이내**를 보고하고, 읽어 보라고 한다.
6. `submit` 을 이어서 할지 묻는다. 시키지 않은 게시를 하지 않는다.

## `edit <raw 경로 | Notion URL | page id>`

1. 초안을 받아 온다:
   ```
   node ${CLAUDE_SKILL_DIR}/scripts/draft-pull.js <대상> [--service <slug> --category <slug>]
   ```
   `--service`·`--category` 는 그 페이지가 `raw/` 미러에 없을 때만 필요하다.
2. `"중단:"` 이 나오면 그 이유(민감·폐기·하위 페이지 포함·위키 페이지)를 그대로 전하고 멈춘다.
3. 초안의 **본문은 Notion 형식(enhanced markdown)** 이다. 표 `<table>`·탭 들여쓰기·`\<` 이스케이프를 **유지**하며 고친다.
   형식을 표준 마크다운으로 되돌리지 않는다.
4. `## 변경 이력` 에 오늘 날짜 항목을 추가한다: `- YYYY-MM-DD (사람 이름) 무엇을 바꿨나`.
   이름을 모르면 묻는다. 본문을 고치지 않고 속성만 바꾸는 경우에는 필요 없다.
5. 사람에게 무엇을 어떻게 고쳤는지 알리고 `submit` 여부를 묻는다.

## `submit <초안 경로> [--apply]`

1. 항상 dry-run 을 먼저 돌린다:
   ```
   node ${CLAUDE_SKILL_DIR}/scripts/draft-submit.js <초안 경로>
   ```
2. 출력을 **그대로** 사람에게 보여 준다 — 대상 데이터베이스, 속성 표(담당자는 이름 → 사용자 id), 본문 크기, 수정이면 diff.
   `E` 오류가 있으면 초안을 고친 뒤 다시 돌린다. `W` 경고는 사람에게 알리고 판단을 받는다.
3. 사람이 확인하면:
   ```
   node ${CLAUDE_SKILL_DIR}/scripts/draft-submit.js <초안 경로> --apply
   ```
4. 결과를 보고한다: 만들어진 페이지 URL(또는 교체 결과)과 `raw/` 기록 경로.
5. 색인·위키는 자동으로 갱신되지 않는다. **`notion-llm-wiki` 스킬의 `ingest`(또는 `build-index`)를 이어서 할지 묻는다.**
6. 게시가 끝난 초안 파일은 지워도 된다고 알린다. 남겨 두면 다음 수정 때 기준이 낡아 중단된다.

## 자주 하는 실수

- **요약·담당자를 추측해서 채우는 것** → 규칙 1 위반. 색인 한 줄과 문의 경로가 함께 틀어진다.
- **`## 미확정 · 열린 질문` 을 비워 두는 것** → 위키가 이 섹션을 사실로 쓰지 않는다. 모르는 것은 여기에 질문으로 남긴다.
- **수정 초안의 본문 형식을 표준 마크다운으로 되돌리는 것** → 제출 때 정규화하지 않으므로 표·이스케이프가 깨진다.
- **dry-run 없이 `--apply`** → 규칙 3 위반.
- **"중단:" 을 보고 다시 시도하는 것** → 이유가 사라지지 않는다. 사람에게 전한다.
- **`확정` 페이지를 말없이 고치는 것** → 규칙 5. 대상 상태를 말하고 확인을 받는다.
